# Team workflow

## Branches

```
main                    always builds; protected by review
  └─ <name>/<topic>     e.g. roger/data-cleaning, samri/xgboost
```

Never commit to `main` directly. One branch per chapter or per focused change.

## Before your first commit

```bash
pre-commit install
```

`nbstripout` strips notebook outputs on commit. Without it, every commit carries
base64-encoded plot images and an `execution_count` that changes on every run —
which makes diffs unreadable and guarantees conflicts when two people touch the
same notebook. Outputs are regenerated by `make report`.

## Pull requests

1. Branch, work, commit.
2. `make test && make lint` before opening the PR.
3. Open the PR; describe what changed and what a reviewer should check.
4. Anyone with time reviews. One approval merges.

Keep PRs to one chapter or one `src/` module where you can. A PR that touches
five notebooks is a PR nobody will review carefully.

## Where code goes

| Kind of code | Location |
|---|---|
| Reads a file | `src/wildfires/io.py` |
| Normalises or validates | `src/wildfires/clean.py` |
| Joins sources | `src/wildfires/merge.py` |
| Derives a variable | `src/wildfires/features.py` |
| Plots (reusable) | `src/wildfires/viz.py` |
| Fits a model | `src/wildfires/models/` |
| Narrative, one-off plots, interpretation | the notebook |

Rule of thumb: **if a second chapter would want it, it goes in `src/`.**

## Conflicts on a notebook

With nbstripout installed these are rare and small. If one happens, prefer
`git checkout --theirs` / `--ours` on the whole file and re-apply your cells by
hand — hand-merging `.ipynb` JSON is not worth the time.

## Scratch work

`notebooks/scratch/` is gitignored. Explore freely there; nothing needs a PR.
Promote to a numbered chapter only when it is presentable.
